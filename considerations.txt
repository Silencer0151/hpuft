The Problem: The Invisible Tail

If we look at heartbeat.go, the receiver dynamically bounds its NACK scanning window between HighestContiguous + 1 and HighestReceived + 1. It is explicitly programmed to "Never NACK sequences the sender hasn't transmitted yet".

During the main transfer, this is a brilliant design. However, consider what happens when the very last packets of the file (the tail) are dropped by your tc netem 0.1% loss rule:

    The sender finishes transmitting all 784,899 packets and enters the teardown loop waiting for TRANSFER_COMPLETE.

    Because the tail packets dropped, the receiver's HighestReceived never advances to the end of the file.

    The receiver scans for NACKs. Because HighestContiguous and HighestReceived are now effectively identical (stuck right before the dropped tail), the scan range is empty.

    The receiver dutifully sends a heartbeat with exactly 0 NACKs.

    The sender receives the heartbeat, sees 0 NACKs, assumes the receiver is just busy flushing to disk, and does nothing.

    Since the sender sends nothing, the receiver's delivery rate stays at 0.00, and after 5 seconds of silence, the receiver's inactivity timeout kills the session.

🛠️ The Fix: Proactive Tail Retransmission

Because the receiver literally doesn't know the tail exists, it cannot ask for it. The sender must detect this deadlock and proactively push the missing tail packets.

In sender.go, inside your Teardown Loop, update the PacketHeartbeat case. If the receiver reports 0 NACKs but its HighestContiguous is less than the end of the file, the sender must artificially inject those missing sequences into the retransmit pipeline.

Modify your teardown heartbeat handler to look like this:

case protocol.PacketHeartbeat:
    hb, err := protocol.UnmarshalHeartbeat(pkt.Payload)
    if err != nil {
        continue
    }

    nacksToProcess := hb.NACKs

    // --- TAIL DROP DEADLOCK PREVENTION ---
    // If NACKs are empty but the receiver hasn't finished the file, the tail dropped.
    // The receiver doesn't know the tail exists, so we must artificially NACK it here.
    if len(nacksToProcess) == 0 && hb.HighestContiguous < totalChunks-1 {
        startSeq := hb.HighestContiguous + 1
        // Bounded to 167 max NACKs per heartbeat to match the protocol spec limits
        for seq := startSeq; seq < totalChunks && len(nacksToProcess) < 167; seq++ {
            nacksToProcess = append(nacksToProcess, seq)
        }
        dbgLog.Printf("[sender] teardown tail-drop: proactively pushing %d missing tail packets", len(nacksToProcess))

The Physics of the Win: Why FTP Choked

FTP uses TCP. TCP uses a congestion control algorithm based on AIMD (Additive Increase, Multiplicative Decrease).

    The TCP Panic: When TCP detects your 0.1% tc packet loss, it assumes the network is severely congested. It instantly cuts its transmission speed (Congestion Window) in half.

    The Latency Trap: Because you have a 100ms RTT (50ms delay each way), it takes TCP a very long time to slowly grow its window back up. By the time it starts getting fast again, another 0.1% loss hits, and it cuts the speed in half again. TCP essentially traps itself at 1.23 MB/s.

Keep it simple: The moment the main send loop finishes and you enter the teardown loop, change the progress bar text from 100% | 40 MB/s to 100% | Repairing lost packets... so the user knows the network is just cleaning up the tail.
